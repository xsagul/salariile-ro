# Homepage: propunere de redesign, 14 septembrie 2026

Ramură: `codex/homepage-intentie-2026-09-14`. Bază: `4e8c580` din `main`.
Propunere pentru verificarea proprietarului. Nu se unește și nu se publică pe salariile.ro fără aprobarea lui.

## Evaluarea paginii actuale

Pagina răspunde intenției corecte, dar cere prea multă scanare înaintea rezultatului.
În captura desktop inspectată, formularul începe în jurul coordonatei verticale 360 px;
netul este al șaselea rând al tabelului. Spațiul dintre antet, introducere și formular
este mare, iar coloana formularului se întinde după tabel și rămâne goală dedesubt.
Tabelul fără valori arată opt indicatori înainte ca vizitatorul să fi introdus o sumă.
Cotele și reperele sunt repetate în introducere, rezultat, articol, card și FAQ.
Există două date diferite afișate sub aceeași etichetă de actualizare, iar starea
goală are „lei lei”. Închiderea opțiunilor avansate resetează pe ascuns datele.

## Intenția și deciziile

Search Console a fost consultat pentru homepage, perioada 15 august–11 septembrie.
Interogările conducătoare sunt „calculator salariu net”, „calculator salariu net 2026”,
„calculator salariu” și „calcul salariu net”. Nu folosim poziția sau CTR-ul ca dovadă
că o problemă vizuală a provocat o scădere. Redesignul este o ipoteză de îmbunătățire a utilizării.

| Element | Decizia și motivul |
| --- | --- |
| Titlu SEO și H1 | Păstrate: intenția generică de calculator rămâne pe `/`. |
| Introducere | Două propoziții despre sarcina imediată; actele normative urmează după calculator. |
| Primul ecran | O singură suprafață, formular și rezultat alăturate pe desktop, în ordine pe mobil. |
| Rezultat | Netul în bani apare primul, mare; în sens invers se evidențiază brutul estimat. |
| Starea goală | Instrucțiune scurtă, fără tabel cu liniuțe sau salariu precompletat arbitrar. |
| Taxe | Total și cost angajator în rezumat; defalcarea, baza impozabilă, deducerea și facilitatea la cerere. |
| Tichete | Banii și cardul de masă rămân separate. |
| Opțiuni | Etichetă concretă: „Tichete, deduceri și scutiri”. Închiderea păstrează datele; resetarea are buton explicit. |
| Exemple | Sumele nete sunt calculate din motorul fiscal, lângă brut și cu ipotezele declarate. |
| Repere BASS | Scoase din homepage: nu rezolvă conversia individuală. Pagina despre salariul mediu rămâne accesibilă. |
| FAQ | Șase întrebări relevante direct; încă cinci într-un grup suplimentar. Toate răspunsurile sunt în HTML și corespund JSON-LD. |
| Hub de salarii | Secțiune scurtă după calcul și explicații; nu concurează cu formularul. |
| Identitate | Paleta caldă, Inter și marca existente. Fără imagini decorative, culori noi sau slogan nou. |
| Încredere | Metodologie, surse, autor și o dată editorială unică; perioada fiscală are etichetă distinctă. |

Formulele fiscale nu se schimbă. Varianta compactă este activată printr-un prop numai pe homepage.
Paginile istorice, generatorul de fluturaș și calculatorul în engleză păstrează prezentarea existentă.
Codul static, URL-urile, canonicul, linkurile fără prefetch și configurația de producție rămân în aceeași arhitectură.
Modificarea testului BASS reflectă eliminarea deliberată a acelui card, nu relaxarea unei verificări fiscale.

## Ce se poate verifica în fișierul HTML

`homepage-redesign.html`, livrat în conversație, este un export autonom: CSS și fonturi din build, plus calculatorul
și meniul din componentele reale. Poate fi deschis fără server. Linkurile către alte pagini
deschid site-ul actual. Exportul nu include analytics și are `noindex,nofollow`.
PDF-ul se generează local. Copierea linkului depinde de permisiunea clipboard și de contextul
HTTPS; fișierul local nu este o adresă publică de distribuție a calculelor.

Fișierul este o previzualizare, nu un înlocuitor pentru testarea aplicației Next/Cloudflare.
Nu se încarcă în `public/` și nu intră în paginile publicate ale site-ului.

## Verificare și limite

- `tsc --noEmit`: fără erori.
- ESLint: fără erori; avertismente preexistente în proiect.
- Suita `npm test`: toate verificările au trecut, executând intrările `tsx` cu `node --import tsx` pentru a evita mecanismul IPC indisponibil în mediu.
- Build Next în modul webpack: compilare, TypeScript și export static reușite.
- Teste DOM de interacțiune: input gol, brut→net, net→brut, rezultat învechit, PDF dezactivat până la recalcul, tichete păstrate după închidere, reset explicit, salariu minim și anunțare accesibilă.
- Motorul existent poate produce o diferență de un leu la inversare în cazul testat. Rezultatul este etichetat „brut estimat” și explică rotunjirea. Nu s-a modificat algoritmul fiscal în acest redesign.
- Browserul cloud refuză serverul local și fișierele locale. Nu pretindem verificare vizuală finală pe desktop/mobil și nici scor Lighthouse.
- `test:rendered` local este blocat de runtime-ul Wrangler (`uv_interface_addresses`); verificarea HTTP completă trebuie confirmată de CI înainte de merge.
